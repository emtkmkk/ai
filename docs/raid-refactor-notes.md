# レイド計算（getTotalDmg）整理メモ

`src/modules/rpg/raid.ts` の `getTotalDmg` を整理する作業のメモ。作業の順番と完了条件は [rpg-refactor-plan.md](./rpg-refactor-plan.md) にある。

進め方:

1. **段階0〜1（構造だけを変える）**: ゴールデンテスト（`test/modules/rpg/raid-golden.spec.ts`）のスナップショットを 1 文字も変えずに、状態をまとめて段階ごとの関数・スキル登録に分ける。
2. **段階2（挙動を変える）**: 下の「気になる挙動」を 1 件ずつ別コミットで直す。各コミットにスナップショットの変化（ダメージの増減）を書く。
3. **段階3**: 通常戦闘（`rpg/index.ts`）にゴールデンテストを足し、同じスキル定義を使う。

段階1の途中で見つけた挙動は、その場では直さずにここへ書き足す。

## ゴールデンテストの範囲

- 水曜日（調子補正が曜日と週で決まる）・詳細ログ（`-v`）あり/なし・土曜日の 3 通り × 8 構成 × 全レイドボス × 乱数 3 通り。
- 乱数は `Math.random` の差し替えで固定しているので、乱数を引く順番が変わっても検出できる（ラベル付き乱数より厳しい）。

## 気になる挙動（段階2の候補）

### 土属性剣攻撃（dart）の代わりの効果が、他の属性と違う条件で出る

- 他の属性スキルが本来の効果の代わりに攻撃力・防御を上げるのは「非戦闘時（`!(isBattle && isPhysical)`）」だけ。
  - 風 `spdUp`: 非戦闘時 攻撃力 ×(1+spdUp)
  - 炎 `fire`: 非戦闘時 攻撃力 +Lv×3.75×fire
  - 氷・光・闇: 非戦闘時 防御 ×(1+…)
- 土だけは `!(isBattle && isPhysical && maxdmg)` で、**戦闘中でも最大ダメージ制限がない敵なら** 攻撃力 ×(1+dart/2) が出る。
- レイドボスには `maxdmg` を持つ敵が 1 体もいないので、**レイドでは本来の効果（最大ダメージ制限 +18%）は一度も出ず、常に攻撃力 +9%（土曜日は +15%）になる**。
- スキル説明（`skill-data.ts` の info）は「非戦闘時、攻撃力+9%」で、実際（戦闘中でも出る）と合っていない。`SKILL_EFFECTS.md` の「それ以外: パワー ×(1+dart/2)」は実装どおり。
- 効果量そのものは突出していない。2026-11-16 時点の試算（スキルなしの構成との比較、通常型のレイドボス 15 体 × 乱数 40 通り、水曜日、5 個積み）:
  - 土 ×5: 多くのボスで +25〜40%
  - 風 ×5・雷 ×5: 土とほぼ同じ
  - 遂（連続攻撃完遂率上昇）×5: +33〜53%（代わりの効果は攻撃力 ×(1+0.32/3) で、土の +9% より高い）
  - パワーアップ ×5: +30〜49%
  - 炎 ×5: ボスによって +1〜600%
- 掛かる順番: 風（非戦闘時、ループ前）・遂・土（どちらもターンごと）は、どれも同じ攻撃力に掛け算で重なる。順番が違っても結果は同じ。レイドでは土・遂がアイテムより前に掛かるので、武器の固定ボーナス（Lv×4×effect）は増えない。通常戦闘（`rpg/index.ts`）ではアイテムのあとに土が掛かるので、武器のボーナスも増える。

### 代わりの効果（パワー倍率）の掛かる位置が、スキルによって違う

- ダメージは攻撃力に比例する（`utils.ts` の `getAtkDmg`）ので、「パワー +x%」はそのまま「ダメージ +x%」になる。倍率どうしは掛け算なので、順番が違っても同じ値になる。
- ただし、掛かる位置の違いで、**途中で足される固定値に倍率が掛かるかどうか** が変わる。
  - 風（`spdUp`）の代わりの効果は、ターンのループの前（`_atk` を保存する前）に掛かる。
  - 遂（`abortDown`）と土（`dart`）の代わりの効果は、ターンごとに `atk = _atk` で戻したあとに掛かる。
  - その間に、次の加算がある。
    - 継戦融合武装（`itemAtkStock`）: 前のターンのアイテムのパワー上昇の 55% を `atk += itemAtkStock` で足す。
    - 攻めの守勢（`guardAtkUp`）: 防御の一定割合を `atk +=` で足す。
  - そのため、この 2 つの加算分には **遂・土の倍率は掛かるが、風の倍率は掛からない**。
  - 継戦融合武装の加算分は、前のターンのアイテムのパワー上昇（その時点の攻撃力に比例するので、遂・土の倍率をすでに含む）から作られる。そのため、**遂・土の倍率はこの分に 2 回掛かる**。
  - 逆に、毒（`weak`）が敵の攻撃力を下げる量は `atk * weakX` から計算するので、風の倍率は反映されるが、遂・土の倍率は反映されない。
- 差は継戦融合武装・攻めの守勢・毒を一緒に持つ構成でだけ出る。
- **対応済み（2026-11-16）**: 遂・土の代わりの効果を、風と同じくターンのループの前に移した（発動条件は戦闘中に変わらない）。3 つとも同じ位置になり、継戦融合武装の分に 2 回掛かることはなくなった。ゴールデンテストでダメージが変わったのは「ベテラン5スキル + 究極」（継戦融合武装 + 究極のお守り）だけで、-0.59%〜+0.04%。他の構成は、詳細ログで遂・土の行が毎ターンから戦闘前の 1 回に変わっただけ。

### コンテスト型（鳩車）で、スキルによる「仕上げ」が常に 0 になる

- `getTotalDmg3` と、確認表示の `getHatogurumaEffectString` の両方で、`fix += Math.floor(skillEffects.abortDown / 4)` のように `Math.floor` している。
  - 対象は連続攻撃完遂率上昇（`abortDown`）・粘り強さ（`tenacious`）・気合で頑張る（`endureUp`）。
- 効果量は 1 未満なので、切り捨てると常に 0 になる。表示は「仕上げ+8%」（`Math.ceil(abortDown * 25)`）なので、意図は `abortDown / 4`（0.32 / 4 = 8%）で、`Math.floor` が余計だと思われる。
- 確認表示の最後の「仕上げ: 0%」も同じ計算なので、表示と実際は一致している（どちらもスキルの分が 0）。

### 同じ計算・表示を複数の場所に書いている（スキルを足すときに書き漏れが起きる）

- パワー倍率などの式: 戦闘の計算（raid.ts）・詳細ログ（raid.ts）・確認表示（effect-display.ts の `stats`）の 3 か所。
- 覚醒変更の札（朱・青・黄・緑）の補正: raid.ts・rpg/index.ts（2 か所）・skills.ts の `getTotalEffectString` の 4 か所。
- コンテスト型の器用さ・仕上げ: `getTotalDmg3`（raid.ts）と `getHatogurumaEffectString`（skills.ts、「RPG スキル バフ 鳩車」）の 2 か所。式は同じで、見出しの言葉だけ違う（例: 戦闘ログは「気性穏やか」、確認表示は「非戦闘時パワー」）。

### ステータス上昇の重なり方が、番号付きのキー（atkUp〜atkUp6）で決まっている

- `aggregateSkillsEffects`（skills.ts）は、同じキーの値を足し、最後に `(1+atkUp)×(1+atkUp2)×…×(1+atkUp6)×1.04^atkUpBonus` で掛け合わせる。
  - つまり「同じキー = 足し算」「違うキー = 掛け算」。
- キーとスキルの対応:
  - atkUp: パワーアップ / defUp: 防御アップ
  - atkUp2・defUp2: 伝説 と 連続・毎日ボーナス強化（**別のスキルが同じグループ**なので、この 2 つは足し算になる）
  - atkUp3・defUp3: 気合で頑張る
  - atkUp4・defUp4: 不運チャージ
  - atkUp5: 気性が荒い・気性穏やか
  - atkUp6・defUp5: かるわざ（攻撃と防御で番号がずれている）
  - atkDmgUp2: すぐ決死の覚悟をする
  - atkUpBonus: 19 スキル。1 個ごとに ×1.04 の掛け算（3 つ目の重なり方）
- 合成お守り（`mergeSkillAmulet` → `mergeSkillEffects`）は効果をキーごとに足して 1 つにまとめる。グループの情報はキーの番号でしか残らない。
- 新しいスキルで独立した倍率を作るには、新しい番号のキーを作り、`SkillEffect` 型・集計の式・確認表示（`merged`）の 3 か所に足す必要がある。

### スキル説明文（info）が固定の文字列で、効果量を参照できない

- 78 スキル中 66 スキルの info に数値が直書きされている（例: 土属性剣攻撃の「制限を18%増加」「+9%」と `effect: { dart: 0.18 }`）。効果量を変えると説明文も手で直す必要があり、ずれても気づけない（土の発動条件の説明がずれていたのもこの形）。
- 実際の効果量は、スキルX倍のボス・曜日（×5/3）・お守り整備・分散型・初心者向けの補正・水（氷・雷を強化）などで変わるが、説明文には出せない。
- 「`showSkillBonus && info ? info : desc`」の選び方が、スキル一覧・変更・選択・複製・カスタムお守りの店・お守りの店などに散らばっている（skills.ts・index.ts・shop.ts・shop-custom.ts）。

### 朱覚醒の詳細ログが別の値を表示している

- 「クリダメ+35%」と書きながら、表示している値は `skillEffects.atkDmgUp`（`critDmgUp` ではない）。`atkDmgUp` を持たない構成では `NaN%` になる。

### 1ターン目のアイテム最低効果が無視されることがある

- `Math.max((count !== 1 ? 0 : skillEffects.firstTurnItemChoice), itemMinEffect)` で、`firstTurnItemChoice` がないと 1 ターン目は `NaN` になる。`!mEffect` が真になるので、`itemMinEffect`（最低効果）が 1 ターン目だけ効かない。

### 紛らわしい書き方（挙動は正しい）

- 毒属性の処理の中で `const arpenX` を同じ名前で宣言し直している（外側の防御貫通とは別の値）。二重に掛かっているように見える。
- `let maxdmg` は字下げがずれているが、ターンのループの中にある（ターンごとに初期化される）。

## 意図した仕様ではないが残すと決めた動き

- **レベルアップで 7 を崩さない補正が、旅ではない敵との戦闘でも掛かる**（2026-11-16 決定）
  - 補正の条件は「旅の最高ステージ 100 以上・パワーか防御に 7 がある・敵がいないか旅の敵」。勝ち・負けで決着すると、レベルアップより前で敵が消えるので、旅ではない敵に勝ったプレイでも補正が掛かる。
  - 本来は旅だけの想定だったが、直すとプレイヤーにとって不便になるだけなので、この動きのまま残す。`battle-golden.spec.ts` のテストで今の動きを固定している。
