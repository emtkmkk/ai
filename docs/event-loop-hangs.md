# イベントループ停止の調査と対策

## 2026-09-08時点の判断

2026-08-31、09-02、09-07の通知は、それぞれ約231秒、233秒、60秒のタイマー遅延を示す。直前の通常ログ、CPUプロファイル、ホストの負荷記録がないため、発生原因は未確定。

- `lastWakingAt` は10秒ごとの生存記録で、機能の起床イベントではない。「通知時刻との差が遅延+約10秒」は監視周期と一致し、特定処理の証拠にはならない。
- `timers: 0` はDBに永続化したモジュールタイマーの数。Node.jsの `setTimeout` / `setInterval` が存在しないという意味ではない。
- メモリ値は停止から復帰した後の1時点。3件で近い値でも、停止中のGC、スワップ、ホスト側の資源不足は判定できない。
- 旧監視は `Date.now()` の差を利用しており、大きな時計の進みも停止と誤検知し得た。今回、単調増加時計 `performance.now()` に変更した。

## 実装から確認した停止経路

迷路は `maze/index.ts` → `genMaze` → `renderMaze` → `canvas.toBuffer()` をメインプロセスで同期実行していた。`async` 宣言や開始前の3秒待機では、これらの計算は別スレッドに移らない。5分制限も同期処理の完了後に判定していたので、処理中には効かなかった。

特にサイズ200以下の生成には、掘れる場所をランダムに選ぶたびに盤面全体を走査するループがあり、掘り進めない場所も候補に含まれる。日次投稿で選ばれ得るサイズ196、シード `2026-8-7/mkck` を既存コードで実行したところ、ローカルNode.js v22.15.0では15秒以内に完了せず、試験用の親プロセスから終了した。これは重い経路の確認であり、当日の実際のサイズや今回の停止原因を再現したものではない。

生成・描画を一時的な子プロセスへ移し、親側の5分タイマーから強制終了できるようにした。アルゴリズムや画像内容は変更していない。同時生成を1件に制限し、失敗時のメンション処理も例外を捕捉する。

ほかに以下の同期処理を確認し、1秒以上かかった実行を診断対象にした。

- `db.serialize`: LokiJSのDB全件JSON化。書き込み自体は非同期でもJSON化は同期。自動保存周期は1秒で、生存記録だけでも10秒ごとにdirtyになる。保存方式・頻度は今回変更していない。
- `chart.render`: チャート描画とPNG変換。
- `reversi.thinkSimple` / `reversi.thinkSuperSimple`: 現行の同一プロセス内の思考。旧 `Session` の深い探索とは別経路。
- `keyword.makeBananasu`: 学習語リストの反復走査・文字列正規化。

## 再発時の読み方

通知と通常ログの `Hang diagnostics` に次を追加した。

- `sample.elapsedMs`: 前回の監視からの実経過時間。通常の10秒も含む。
- `sample.cpuUserMs` / `cpuSystemMs`: 同じ区間のプロセスCPU時間。全スレッド合計なので、GCなども含み、実経過時間を上回る場合もある。特定のJS関数のCPU時間ではない。
- `sample.wallClockDeltaMs`: 壁時計の進みと単調増加時計との差。時計調整の手掛かり。
- `slowSync`: 計測対象のうち1秒以上かかった同期処理の名前、所要時間、終了日時。直近10分の最大8件。引数、本文、ユーザーID、戻り値は保存しない。

`slowSync` の終了日時と所要時間が停止区間に重なれば、その経路を優先して調査する。CPU時間も大きいなら計算・GCを、CPU時間が小さいなら同期I/O、CPU割当不足、ホスト停止などを候補にする。ただしCPU時間だけで原因は断定できない。`slowSync` が空でも、計測していない処理による停止は除外できない。

次に必要な証拠は、再発通知と同時刻の通常ログ、およびホストのCPU・swap・I/O待ち・プロセス停止/再開の記録。今回の変更だけで本番の再発解消を確認したとは扱わない。

## 検証範囲

`npm run build` とJestで、子プロセスの正常応答、異常終了、不正応答、同時実行制限、停止した子の時間切れ終了・次の処理への復帰、親タイマーの継続、時計補正とCPU差分、診断記録の件数・保存時間・引数非保存を確認する。

今回のローカル検証結果はビルド成功、12スイート・70テスト成功。全体実行は `test/message.spec.ts` のAPIモックが返すユーザーの欠落で中断するため、これを除外して残りを実行した。その際の `test/modules/rpg/skills.test.ts` のimport中の `undefined.filter` エラーを含め、両方の失敗を変更前のHEAD `7e698853` の一時コピーでも再現した。今回の修正により全テストが成功した、という状態ではない。

ローカルでは `canvas/build/Release/canvas.node` が欠けているため、実CanvasによるPNG生成は未確認。子プロセス通信のテストは専用fixtureを使用しており、画像描画の試験を代替するものではない。本番Node.js v18.15.0での起動、迷路画像の生成・投稿、再発有無は別途確認が必要。
