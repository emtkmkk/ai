# yesno

Claude API を使って「はい/いいえ」質問に答えるモジュールと、その回答サービス。

## 処理の流れ

```mermaid
flowchart TD
    A["メンション受信"] --> B{"「ですか？」「ますか？」<br/>「ですよね？」で終わる?"}
    B -- はい --> C["dice モジュールが<br/>YesNoService.answer()"]
    B -- いいえ --> D{"他のモジュールが<br/>反応した?"}
    D -- はい --> Z["（このモジュールは何もしない）"]
    D -- いいえ --> E{"疑問文らしい?<br/>（？ / か / よね など）"}
    E -- いいえ --> Z
    E -- はい --> F["yesno モジュールが<br/>YesNoService.answerIfQuestion()"]
    C --> G
    F --> G{"メモリーに<br/>過去の判定がある?"}
    G -- はい --> K
    G -- いいえ --> H{"Claude が使える?<br/>（キーあり・上限内）"}
    H -- いいえ --> R["質問テキストをシードにした乱数"]
    H -- はい --> I["Claude に問い合わせ<br/>（規格外・失敗なら1回だけ再試行）"]
    I -- 2回とも駄目 --> R
    I -- 判定を取得 --> J["メモリーに保存"] --> K{"判定"}
    K -- 質問でない --> L["語尾一致: 不定扱い / それ以外: 返信しない"]
    K -- undetermined（不定） --> U["返信せず :thinking_mkchicken: をリアクション"]
    K -- yes / maybe_yes /<br/>maybe_no / no --> M["固定の文言で返信"]
    R --> M
```

## 回答

Claude の応答は JSON Schema で `isYesNoQuestion`（真偽値）と `answer`（5択）に固定し、
さらにプログラム側で検証してから固定の文言に変換する。Claude の文章がそのまま返信に流れることはない。

| answer | 返信文言 |
| --- | --- |
| `yes` | はい |
| `maybe_yes` | 多分はい、部分的にはい |
| `maybe_no` | 多分いいえ、部分的にいいえ |
| `no` | いいえ |
| `undetermined` | 返信しない。`:thinking_mkchicken:` をリアクションする |

`undetermined`（不定）は「分からない」ではなく、答えが一つに定まらないことを明確に示す特別な返答。
明らかに不定であることが確定的な場合（性格設定で不定とされている事柄、存在の位置づけ上定まらない事柄、質問自体が答えを一つに定められない構造のもの）のみ使う。
知らないこと・時間で変わること・判断に迷うことは不定ではなく、4択で答える。Claude が使えない・応答が規格外・通信失敗のときは、
これと区別して従来どおり質問テキストをシードにした乱数で4択から選ぶ。
乱数のシードと閾値は従来の dice モジュールと同じなので、Claude が使えない環境では以前と同じ回答になる。

## 一貫性

- Claude には「原則4択から選び、undetermined は明らかに不定であることが確定的な場合のみ」と指示している。
- 判定はメモリー（`_yesno_answers` コレクション）に質問テキスト単位で保存し、同じ質問には同じ答えを返す。
  不定や「質問でない」という判定も保存し、同じ質問で再び API を呼ばない。保存件数の上限は 10,000 件で、超えた分は古いものから消す。
- 質問テキストは前後の空白と連続空白だけを正規化してキーにする。

## 設定（config.json）

| キー | 型 | デフォルト | 説明 |
| --- | --- | --- | --- |
| `anthropicApiKey` | string | — | Claude API のキー。無ければ環境変数 `ANTHROPIC_API_KEY` を使う。どちらも無ければ乱数のみで動く |
| `yesNoClaudeEnabled` | boolean | `true` | Claude を使うかどうか |
| `yesNoModel` | string | `claude-haiku-5-5` | 使うモデル |
| `yesNoCharacterFile` | string | `<memoryDir>/yesno-character.md` | 性格設定ファイル（Markdown）のパス。**git 管理外に置く** |
| `yesNoDailyLimit` | number | `300` | 1日あたりの Claude 呼び出し上限（コストの安全弁）。0 以下で無制限 |

### 性格設定ファイル

ボット自身の好みや考えを問われたときの根拠になる。Markdown で自由に書く。
ファイルが無い場合は性格設定なしで動き、ボット自身に関する質問は不定（リアクションのみ）になる。
リポジトリの `.gitignore` に `yesno-character.md` を入れてあるので、既定の場所に置けば git には入らない。

## 仕様

| 項目 | 内容 |
| --- | --- |
| 使用フック | `mentionHook`（モジュール配列の最後に登録） |
| リアクション | 回答時 `love`。不定時 `:thinking_mkchicken:`（返信なし） |
| 公開範囲 | 語尾一致（dice 経由）は従来どおり `public`。フォールバック判定分は元投稿の公開範囲に合わせる |
| タイムアウト | 1回の問い合わせ 20 秒。SDK 側の自動再試行は無効にし、サービス側で1回だけ再試行 |
| テスト環境 | `NODE_ENV=test` では Claude を使わない |

## ファイル

| ファイル | 役割 |
| --- | --- |
| `service.ts` | 回答の決定ロジック（メモリー・Claude・乱数の優先順、応答の検証、再試行） |
| `claude-client.ts` | Anthropic SDK の呼び出しとシステムプロンプト |
| `index.ts` | モジュール本体と、dice と共有するサービスの生成 |
